# RQ1 correction

This note records the corrected conjunction rule and the escalation terminology. It does not replace the historical Phase F1, F2, or F3 result files.

## What changed

A conjunction is `violated` when any permitted, sufficiently strong conjunct is false, including when another conjunct is unavailable. `holds` still requires every conjunct to be usable and true. Otherwise the evaluation stays unavailable. The classifier does not read an unavailable value and does not call the world oracle. The evidence witness for a violation is the public false conjuncts when one exists, so atom order does not change a public decision into `checkable_with_escalation`.

`architect_escalation_for_uncheckable_invariant` applies only while that world remains uncheckable. A world established as `violated` has formation `block` on the escalation row and applicability `not_applicable`. It is not counted as an escalation. T0 acceptance is unchanged: a checkable `holds` evaluation may accept, including under the legacy label `checkable_with_escalation`.

`checkable_with_escalation` is the legacy label for a usable check whose witness is non-public evidence or attestation. The label does not defer formation and does not require an approval event under T0. Tactic approval fields record the cost of introducing a tactic. They do not record that approval occurred. A `T1:<tactic_id>` row is a tactic condition, not the architect-escalation condition.

Aggregates and recovery relations were not given this partial rule.
